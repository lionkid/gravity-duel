Assessment

「2.5D」有兩種意思，建議採用第一種

A · 視覺 2.5D 建議

  • 3D 立體機體與透視場景，戰鬥仍在同一個平面上。格鬥遊戲界對 2.5D 的標準定義（Street Fighter IV、Guilty Gear Xrd 都是這種）。
  • 這一頁就是這個方案：物理與武器模組一行都沒改，只換了 renderer。
  • 重力彈道的核心玩法完全保留，抬高瞄準、拋物線、太空直線都看得清楚。
  • 鏡頭會跟著兩人距離拉近拉遠、隨位置微微偏轉，KO 時慢慢繞到勝者身邊。
  • 機體轉身是真的轉過來，不再是鏡像翻轉。
代價：約一個里程碑（已經做出來了）。零外部套件，雙擊 HTML 仍可直接玩。

B · 加深度軸的 2.5D 不建議現在做

  • 像 Virtual-On 或 Gundam vs. 的競技場，可以前後走位閃子彈。
  • 雙人單鍵盤下，上下鍵要同時負責深度移動、瞄準方向、太空推進，按鍵不夠用。
  • 有了側移閃避，瞄準幾乎必須改成自動鎖定，「抬高射角」這個玩家技巧就消失了，重力只剩射程限制。
  • 平台、單向穿越、正面防禦、推擠判定全部要重做。
代價：等於重做一款遊戲，約 3 個里程碑，而且會削弱原本的核心設計。

A+ · 之後可選的加料 M5 以後

  • 側步閃避：下 + 衝刺做一次短暫側步到後方車道，子彈從身邊飛過。保留 2D 核心，加一點深度玩法。
  • Three.js 版本：如果想要真正的陰影、光束 bloom、高模機體，可以把這個 renderer 換成 WebGL。需要載入約 650 KB 的函式庫。
  • 3D 選機畫面：M3 的機體選擇可以直接用這套方塊機體做旋轉展示。
先確認方案 A 的手感，再決定要不要加。

這一版 renderer 做了什麼

項目做法對玩法的影響
投影透視鏡頭、焦距 900 px，自寫 3x3 矩陣與畫家演算法排序，Canvas 2D 繪製無
機體每架約 20 個方塊：頭、軀幹、肩、臂、背包、腿、腳，依狀態擺姿勢；武器依類型掛在手上或肩上無，碰撞盒仍是 2D 矩形
鏡頭對戰模式偏轉最多 ±10°、俯角 6°，依兩人距離自動縮放。偏轉刻意保守，彈道距離感才不會失真需要你實際玩過確認可讀性
場景地球：透視地面格線、廢墟天際線、落日、山脈。太空：星點視差、地球、漂移小行星、場地框線無
特效粒子、爆炸、傷害數字、衝刺殘影全部沿用 2D 版，只是投影到戰鬥平面上無

需要你確認

  1. 方案 A 的畫面與鏡頭你接受嗎？玩幾場，特別感受火箭砲與榴彈的距離是否還好判斷。
  2. 對戰鏡頭的偏轉幅度（目前 ±10°）要更平、還是可以更斜一點？「側面 2D 對照」按鈕就是 0°。
  3. 確認後我會把 render3d.js 設為正式 renderer 並推上 GitHub，接著進 M3 選擇流程。
