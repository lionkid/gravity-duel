# Gravity Duel: Skyline — 架構規劃（草案 v0.1）

> 工作名稱，可改。分支 `skyline`，遊戲放在 `games/skyline/`，可重用的部分放在 `engine/`。
> 這份文件是實作前的藍圖：先把層次、資料契約與里程碑定下來，數值都是起始值，之後靠測試與試玩調整。

## 1. 一句話

Gravity Duel 世界觀下的 3D 第三人稱機甲 1 對 1 對戰：在城市裡跑高速公路、跳上大樓、躲進巷弄；
火神砲直射、近戰鎖定衝刺、遠程武器切進第一人稱瞄準。

### 目標

- 瀏覽器執行，無需安裝（開發時用現有的 `lan-server.js` 或桌面版 launcher 提供服務）。
- 單人對電腦、區域網路 1 對 1。沿用現有的 LAN 伺服器、房間探索、桌面版打包。
- 引擎層（`engine/`）不含任何這款遊戲的規則，下一款遊戲只需提供資料與規則。
- 模擬層不碰 DOM、不碰 Three.js，可在 Node 跑測試，和現在的 `physics.js`/`combat.js` 一樣。

### 非目標（第一版）

- 同一台電腦雙人（3D 加滑鼠瞄準，一台電腦只有一隻滑鼠；分割畫面列為 M5 選項）。
- 外部 3D 模型檔。機體與城市全部程式化產生，和現在「音效用合成、畫面用方塊」的路線一致。
- 可破壞的建築、天氣、劇情。

## 2. 技術選型

| 項目 | 決定 | 理由 | 放棄的選項 |
|---|---|---|---|
| 3D 繪圖 | **Three.js**（ESM，固定版本複製到 `vendor/three/`） | 真 3D 相機、深度、後製都是現成的；自己寫 WebGL 引擎會吃掉所有時間 | 自寫 WebGL（太大）、Babylon（更重）、延用 2.5D Canvas（做不出跳樓頂與第一人稱） |
| 模組系統 | **ES modules + import map** | Three.js 只有 ESM；Node 22 測試可直接 import 同一份檔案 | 傳統 script（Three 已不提供 UMD） |
| 建置工具 | **沒有**。直接服務原始檔 | 和現在一樣零建置；需要單檔時再加 esbuild 一步 | 一開始就上 bundler |
| 供應方式 | **一定走 HTTP**（launcher、`node server/lan-server.js`、claude.ai artifact） | Chrome 不允許 file:// 載入 ES modules | 雙擊 index.html（原作可以，這款不行） |
| 瞄準輸入 | **Pointer Lock API** 優先，鍵盤方向鍵備援 | 第一人稱瞄準需要相對位移的滑鼠；沒有滑鼠或 iframe 不允許時用鍵盤 | 只用絕對座標的滑鼠 |
| 物理 | **自寫**：AABB 世界 + 膠囊／AABB 角色控制器 + 線段掃掠 | 城市是方塊組成，簡單碰撞就夠；確定性、可測試、快照小 | cannon-es / rapier（多一個依賴、快照複雜、非必要） |
| 測試 | Node 測模擬；Playwright headless Chromium 測畫面 | 這個環境的 headless Chromium 有 WebGL2（SwiftShader），可截圖比對 | 只靠人工試玩 |

Three.js 版本在 M0 用 npm 安裝時固定（目前 0.186），只複製 `build/three.module.min.js` 與用到的 `examples/jsm/` 檔案進 `vendor/`，區網對戰不需要外網。

### 依賴規則（用測試守住）

1. `engine/sim`、`engine/core`、`games/*/rules`、`games/*/ai`、`games/*/stages` 不得 import Three 或碰 `window`/`document`。
2. `engine/render` 只讀模擬狀態，不改它；要影響模擬只能透過 Intent。
3. `engine/*` 不得 import `games/*`。遊戲把資料與回呼交給引擎。
4. 事件（聲音、特效）由模擬放進 `events` 佇列，表現層消費；區網時主機把事件附在快照裡送出（同現在的做法）。

## 4. 核心資料契約

一款新遊戲只需要提供這幾樣東西，引擎的其餘部分照用。

### Intent（每 tick 一份，鍵盤／滑鼠／手把／觸控／AI／遠端都產生同一種）

```js
{
  move: { x, z },        // 世界座標方向，長度 0..1。客戶端用自己的鏡頭 yaw 轉好再送，主機不需要知道鏡頭
  aim:  { yaw, pitch },  // 絕對角度（弧度）。第一人稱瞄準與遠程開火用
  held: { boost, attack, guard },           // 持續按住
  pressed: { attack, sub, switch, dash, lock, jump }  // 邊緣觸發，0.15 s 緩衝（沿用現有輸入緩衝）
}
```

遠端送出時編成 4 個 float + 1 個 byte；一開始先用 JSON，LAN 頻寬夠。

### World（模擬狀態，純資料，可整份 JSON 化）

```js
{
  tick, dt, rnd, winner,
  stage: { id, gravity, bounds, statics: [AABB...], ramps: [...], spawns: [...] },
  fighters: [ { id, pos, vel, yaw, aim, onGround, fuel, heat, hp, armor, weaponClass,
                active: 'melee'|'vulcan'|'ranged', phase, timers, lock, stun, guard, ... }, ... ],
  projectiles: [ { id, kind, owner, pos, vel, gravityScale, ttl } ],
  events: [ { t: 'hit', x, y, z, ... } ]   // 每 tick 清空
}
```

### Stage 資料（產生器輸出，模擬與表現層共用）

```js
{
  id: 'city', seed, gravity, bounds: { minX, maxX, minZ, maxZ, ceiling },
  statics: [ { min: [x,y,z], max: [x,y,z], tag: 'building'|'deck'|'rail'|'ground' } ],
  ramps:   [ { min, max, axis: 'x'|'z', from: y0, to: y1 } ],   // 斜坡：足跡 AABB + 線性高度
  spawns:  [ { pos, yaw }, { pos, yaw } ],
  visual:  { blocks: [...], roads: [...], highway: [...], palette }  // 只給 world-builder 用
}
```

### Mech 外觀資料（零件樹）

```js
{ id: 'ax01', palette: { armor, trim, glow }, root: {
    name: 'torso', shape: 'box', size: [8, 7, 5], pos: [0, 11, 0], mat: 'armor',
    children: [ { name: 'head', shape: 'box', ... , children: [ { name: 'visor', mat: 'glow', ... } ] },
                { name: 'armL', ... }, { name: 'thrusterL', shape: 'cone', mat: 'glow', ... } ] } }
```

`mech-builder` 依名稱找到 torso / head / armR / legs / thrusters / muzzle 等節點做程序動畫（跑步、噴射火焰、舉槍、揮砍），所以不同設計只要節點名稱一致就能共用動畫。

### Game 介面（遊戲交給引擎的東西）

```js
{
  config, bindings, screens,
  createWorld(options, seed), step(world, intents, dt),
  serialize(world) / apply(world, snapshot),        // 區網快照
  cameraTarget(world, playerId), hudModel(world, playerId),   // 引擎據此擺鏡頭、畫 HUD
  mechDesign(fighter), stageVisual(world.stage),
  createAI(level, seed), aiIntent(ai, world, playerId, dt)
}
```

## 5. 遊戲系統設計

### 5.1 單位與尺度

公尺、Y 朝上（Three.js 慣例）。機體高 18 m。城市 8×8 個街區、間距 100 m（70 m 建物 + 30 m 街道），
競技場 800 m 見方，外圍是能量圍欄。建物高 25–130 m；高架道路甲板高 16 m、寬 36 m，繞內圈 4×4 街區一圈，四個角落有上下匝道。

重力用「手感重力」：地球 32 m/s²（18 m 的機體用真實 1 g 會飄）。重力是場景參數，沿用世界觀：之後的月面城市會用 1/6，跳得高、彈道平。

### 5.2 移動與碰撞

- 角色是 10×18×10 的 AABB（之後視手感換膠囊）。移動分三軸：先 x 再 z 再 y，每軸碰到就推回。簡單、穩定、確定。
- 踏階 2 m（路緣、欄杆）；貼地讓斜坡與匝道不會「跳格」。
- 跑 28 m/s；衝刺 60 m/s 持續 0.3 s、冷卻 1.2 s，衝刺有短暫無敵。
- 噴射（按住 boost）：向上 45 m/s²，燃料 3 s，落地回充；落地有 0.15 s 硬直，從高處落下不扣血。要在 2 s 內上得了 60 m 的樓頂。
- 投射物：每 tick 用線段掃掠對靜態 AABB 與機體 AABB。視線（LOS）同一個函式。
- 鏡頭碰撞：從機體胸口往鏡頭位置做球體掃掠，有建物就縮短吊臂。

### 5.3 鏡頭

三個鏡頭都在表現層，是各客戶端自己的事；模擬只拿到 Intent。

| 模式 | 進入 | 行為 |
|---|---|---|
| 第三人稱・鎖定（預設） | 戰鬥開始、按 lock | 機體面向對手（轉速有限制），移動變成環繞／橫移；鏡頭站在「對手 → 我」延長線後方 42 m、高 18 m，對手越遠就再拉遠拉高（最多 +30 m／+24 m），視線稍微往對手偏，兩台機體都在畫面裡。FOV 58 |
| 第三人稱・自由 | 再按 lock、或對手失去視線超過 3 s | 滑鼠／右搖桿／方向鍵環繞鏡頭；機體面向移動方向 |
| 第一人稱・瞄準 | **按住瞄準鍵**（右鍵／K） | 鏡頭在頭部，yaw/pitch 直接就是 `aim`；畫面中央準星；FOV 40（長槍 30）；移動速度 ×0.6；身體隱藏只留槍管。放開瞄準鍵就回到第三人稱 |

模式切換用 0.25 s 的位置與 FOV 內插。第一人稱時看不到側後方，是遠程的代價。瞄準鍵對任何武器都有效（可以用來看遠方），但只有遠程武器能在瞄準中開火。

### 5.4 操作

| 動作 | 鍵盤＋滑鼠 | 純鍵盤（備援） | 手把 |
|---|---|---|---|
| 移動 | WASD | WASD | 左搖桿 |
| 鏡頭／準星 | 滑鼠（pointer lock） | 方向鍵（固定角速度） | 右搖桿 |
| 噴射（按住） | Space | Space | A |
| 攻擊（目前武器） | 滑鼠左鍵 / J | J | RT |
| 瞄準（按住，第一人稱） | 滑鼠右鍵 / K | K | LT |
| 切換武器 | 滾輪、1 / 2 / 3 | 1 / 2 / 3 | Y |
| 衝刺 | Shift / L | L | B |
| 防禦 | Ctrl / ; | ; | LB |
| 鎖定切換 | F | F | RB |
| 暫停 | Esc（同時解除 pointer lock） | Esc | Start |

**滑鼠與鏡頭**（`engine/input/mouse.js`、`engine/input/bindings.js`）：開打時要求 pointer lock（先試 `unadjustedMovement` 關掉系統加速，被拒就退回一般鎖定；只有真正被拒才算「拒絕」，連兩次就不再要求）。拿不到鎖定時——嵌入式頁面（claude.ai 的 artifact）不允許、還沒點畫面、用 Esc 從選單回來——滑鼠照樣能轉：遊戲進行中，游標本身的移動就是視角移動，而游標到不了畫面外，所以停在畫面左右 8%（上下 10%）的邊帶裡會依深入程度的平方持續轉向（`settings.edgeRate`，隨靈敏度設定），畫面邊緣出現箭頭提示；游標離開頁面就停。只有「曾經鎖定又失去」才暫停，拒絕不會。視角在每個繪圖幀轉動（`frameLook`：`mapper.look(frameDt)`，tick 只讀按鍵），所以 120 Hz 螢幕上鏡頭一樣順，模擬拿下一個 tick 開始時的視角當 Intent 的瞄準方向；第一人稱開鏡時所有視角輸入乘上 `tan(放大後視角/2) / tan(55°/2)`（步槍約 0.5），同樣的手部移動對應同樣的畫面移動，瞄得更穩。

**鎖定時的鏡頭**：鎖定對手時鏡頭由鎖定 rig 決定，以前滑鼠完全沒作用。現在 rig 記住自己上一幀寫進 `look` 的角度，下一幀 `look` 和它的差就是玩家的輸入（mapper 每幀轉動視角），這個差累積成一個繞著玩家的「環顧」偏移（yaw ±1.35、pitch ±0.6），把平滑過的鏡頭位置與注視點整個剛體旋轉——視角轉動的角度正好等於滑鼠的輸入，玩家停在畫面同一處；手停 0.35 s 後偏移以指數衰減回到正後方。偏移後的鏡頭位置另做一次牆面掃掠。

**可改的按鍵**（`engine/input/keymap.js`，設定裡的「按鍵設定」）：按鍵表複製一份給 mapper（`cloneBindings`），玩家的修改直接改這份（mapper 每 tick 讀表，立刻生效），存檔只存和預設不同的動作（`diffBindings` → `localStorage` 的 `skyline.keys`），啟動時套回預設之上（`applyBindingDiff`，壞資料忽略、重複的鍵只留一個）。每個動作兩格鍵盤／滑鼠鍵，手把配置固定；指定一個鍵時會先從其他動作拿掉（`setKey`）。設定畫面點格子後用 window 的捕獲階段監聽下一次 keydown／mousedown／wheel（搶在選單與遊戲之前），Esc 取消、Backspace 清除。操作說明依目前的表產生（`ACTIONS` 是每個動作的名稱）。

**速度滑桿**（`TUNING`）：跑步與衝刺是模擬數值的倍率（預設 1.4×／1.3×，範圍 0.8–2），存在 `world.tuning`，跑步倍率同時乘上地面與空中的加速度和空中限速，所以手感一樣只是更快；衝刺倍率乘上衝刺速度。單人與練習中調整立刻寫進目前的世界；區網由主機決定——`setTuning` 隨 `hi`／`pick` 送給來賓顯示，並隨 `start` 送出，兩邊用同一組建世界。`hashWorld` 納入倍率，快照與複本自然帶著。

按鍵表是資料（`config.js` 的 `BINDINGS`），引擎不寫死：`Pad:<按鈕>` 是標準配置手把的按鈕，`engine/input/gamepad.js` 每 tick 輪詢、搖桿有死區與響應曲線，選單用 d-pad／搖桿輕撥與 A／B 操作。觸控在 `engine/input/touch.js`：左半邊浮動搖桿（手指落點就是搖桿中心）、右半邊拖曳當鏡頭、右下角按鈕以動作名稱直接對應 Intent，瞄準鍵是切換式；coarse pointer 裝置自動顯示，設定可強制開關。純鍵盤瞄準可開「輕微吸附」：準星靠近目標時角速度變慢（未做）。

### 5.5 武器與防具

開局選 **武器類型**（普通／遠程／近戰）與 **防具**（普通／防遠程／防近戰）。火神砲人人都有。戰鬥中在 近戰／火神砲／遠程 間切換：拔出 0.3 s、冷卻 2.5 s（沿用）。

| 武器類型 | 遠程（第一人稱瞄準） | 近戰（鎖定衝刺） | 火神砲 |
|---|---|---|---|
| 普通 | 火箭砲：90、0.55 s/發、450 m/s、能量 34（回充 20/s） | 光劍：三連 130/130/200（第三段迴旋斬），起手 0.1 s，距離 45 m 內以 220 m/s 衝 30 m | 共用 |
| 遠程 | 長距離步槍：135、1.3 s/發、1200 m/s、能量 55（回充 23/s）、2× 變焦、瞄準時移動 ×0.4 | 短刀：兩連 95/95，起手 0.06 s，衝 20 m | 共用 |
| 近戰 | 手砲：36、0.35 s/發、320 m/s、能量 24（回充 28/s）、實彈受重力（gravityScale 0.5） | 巨劍：300 單發（躍起下劈），起手 0.26 s 有霸體、可破防，以 210 m/s 衝 40 m | 共用 |

**反應速度**（試玩回饋後）：近戰按下攻擊時「衝刺」與「舉刀」同時進行，衝到位就立刻揮，第一刀從按鍵到命中約 0.1–0.2 s（巨劍 0.3 s）；換武器拔出 0.12 s、冷卻 1.6 s，拔刀期間的按鍵會被記住 0.2 s；遠程武器射速與彈速都提高，能量回充跟著調整所以持續輸出不變；鎖定中不按瞄準直接按攻擊會「腰射」鎖定目標（220 m 內、散佈 0.02 rad、不變焦），瞄準仍是精準射擊的方式；按了卻不能射（冷卻、沒能量、沒目標）會有乾扣聲與準星變紅，準星外圈顯示冷卻進度；進瞄準的鏡頭切換 0.12 s；區網來賓的輸入延遲從 2 tick 降到 1 tick 起跳。AI 相應改成逐發判斷閃避（看到砲彈後經反應時間才決定）與每次揮刀只判斷一次防禦，所以快出招真的能搶在它反應前命中。

- **火神砲**：沿身體正前方水平直射的小火箭（260 m/s、看得見彈體與尾焰），錐形散佈 2.9°、射程 150 m、8/發、8 發/秒、過熱 3 s。不能抬頭：對方站在 30 m 的樓頂就打不到。這讓「跳上建築」直接成為對策。
- **遠程**：只有在按住瞄準鍵、處於第一人稱時才能開火。準星用滑鼠或方向鍵，開火沿 `aim` 方向。
- **近戰**：有鎖定且在距離內，攻擊鍵先衝刺再揮砍；沒鎖定就原地揮。
- **防禦**：傷害 ×0.5，巨劍可破防；防禦中不能移動。

| 防遠程 | ×0.8 | ×0.7 | ×1.45 | ×0.88 |

### 5.6 城市場景

`stages/city.js` 吃種子與參數，輸出第 4 節的 Stage 資料，同一個種子永遠產生同一座城市（區網只傳種子）。

- 街區：每格隨機 1–3 棟建物，高度依「離中心距離」分布（中心高、邊緣低），保證每個街區至少一個 25–45 m 的「可上樓頂」跳板，讓高樓可以分段爬。
- 高速公路：繞內圈的矩形環，甲板 AABB、兩側 1.5 m 欄杆（踏階上得去、擋彈）、四個匝道（ramps）。跑在上面最快，但毫無掩蔽。
- 街道：44 m 寬（街區間距 120 m），同一街區內建物彼此留 8–14 m 的巷弄，能擋火神砲與視線。路口有少量矮物件（高架柱、廣告塔）當掩體。
- 圍欄：`bounds` 四面與 300 m 天花板；榴彈類之後碰到就炸（沿用 wallBurst）。
- 視覺：建物 InstancedMesh（一次 draw），窗戶由 shader 畫、以 `uNight` 控制逐棟亮燈。**時間流逝**：比賽從傍晚（t = 0.08）開始，`dusk.toNight` 150 秒後全黑；霧色、太陽、半球光、天空盒、環境貼圖（白天／夜晚兩張 PMREM）與路燈都由 `setTimeOfDay(t)` 在 noon／dusk／night 三組關鍵影格間內插。地面 blob 陰影永遠開（跳躍判斷高度靠它），真陰影是選項。

**出招動畫**：`engine/render/mech-anim.js` 的每種招式有「舉刀」與「收刀」兩組關鍵影格，涵蓋雙臂、軀幹三軸、頭、蹲身與躍起；迴旋斬整台機體轉一圈（`mech.rootYaw`），下劈先躍起再砸下（`mech.rootLift`）。刀刃有獨立材質，舉刀時發光加強、光幕放大；刀光拖尾 0.3 s、斬擊弧兩層（白芯與色弧）並隨時間掃動；重擊、下劈、迴旋、火箭命中與 KO 會放出擴散的衝擊環（`createRings`），開火有白芯槍口光、沿彈道的光痕（步槍 320 m 的軌跡線）與槍口環，後座力動作加大。重擊時全畫面閃白一下並拉長定格。

**月面都市**（`STAGES.moon`，theme `moon`）：同一個產生器換參數——重力 11、街區間距 130 m、街道 56 m、建物 12–64 m（矮樓多），另外在街道上撒 70 顆 3–9 m 高的巨石（`rocks`，避開中央十字、出生點與其他方塊）。視覺主題在 `engine/render/world-builder.js` 的 `THEMES`：灰色地面與隕石坑環（依種子撒、避開建物）、全程夜晚的燈光關鍵影格、天空盒多畫一顆被太陽照亮的地球（`sky.set({ earth })`）。低重力下跳躍頂點約 18 m、滯空 3.6 s，噴射三秒可升一百多公尺——是另一種節奏，平衡測試仍以天際城為準。

**沙漠遺跡**（`STAGES.desert`，theme `desert`）：同一個產生器的 `layout: 'village'`——每個街區是 2–5 間 12–26 m 的土牆房屋（10–46 m 高，偶爾一座瞭望塔），`mesas: 5` 個街區換成兩層的平頂岩山（62–95 m），`emptyLots: 0.25` 的街區是只有幾顆巨石的開闊沙地，沒有高架道路，出生點相距 220 m（`spawnZ`）。城市與月面的產生結果完全不變（另用一個亂數產生器挑岩山與空地）。視覺主題：午後到日落到紫色夜晚的燈光、土牆上稀疏的方窗洞（入夜後少數亮燈）、帶地層紋理的岩山與巨石、沙紋地面、圍欄外一圈沙丘，天空畫出太陽圓盤（`sky.set({ disc })`）。

**軌道站**（`STAGES.space`，theme `space`）：同一個產生器的 `layout: 'station'`——每個街區是一座 12–40 m 的艙段（有時上面再疊一層較高的塔）、兩座中間留 12–16 m 通道的艙段、一個貨櫃場（12 m 長的貨櫃，單層或疊兩層），或一根 60–86 m 的天線桅杆（頂端有閃爍的紅色信標）；30% 的街區是只有零星貨櫃的空甲板。重力 18（略高於半個 g），沒有高架道路，出生點相距 220 m，`meteors: true` 讓世界加上漂流隕石與流星襲擊（5.12）。視覺主題：永遠是夜晚、陽光直射；12 m 鋼板拼成的甲板（板縫與每塊不同的光澤）、會發光的車道邊線、艙段牆面的面板縫、舷窗（多半亮著）與每 12 m 一圈的燈帶、四色貨櫃；甲板只延伸到圍欄外約 250 m，邊緣有厚度、護緣與一圈燈，再過去就是太空。天空：上下都有星星（另有一層更細的星塵）、一道淡淡的星雲，以及一顆帶光環的氣體巨行星——在天空著色器裡用光線追蹤：從眼睛出發對球體與環面求交，條紋沿赤道（環面）方向，行星的影子會落在光環上，球體在前就遮住後面的環。太陽是沒有大氣散射的緊縮光暈。黑色天空會讓圍欄的半透明牆變成一圈發光的地平線，所以這裡的牆幾乎透明，改在甲板上畫一圈發光的界線。

### 5.8 機體外觀

全部程式化，但要「華麗」：多層裝甲板、肩部大型鰭翼、背後像披風的噴射翼、關節與裝甲縫發光（bloom）、頭部多叉冠飾與單一條狀面罩。
噴射時翼展開、火焰拉長；揮砍留光帶；受擊時 trim 閃白。

IP 防線：不用 V 字天線、不用紅藍白黃三色配置、不做「嘴部散熱口 + 雙眼」的臉。四台機體沿用原作的 AX-01 VANGUARD 等名稱與性格（這些是我們自己的設定）。

**機體工房**（`games/skyline/lab.js`，標題選單「機體工房」）：同一個頁面裡的編輯器，不另開視窗，所以單檔下載版也有。遊戲把場景、機體與鏡頭借給它：開啟時 `labOpen` 讓繪圖迴圈改呼叫 `lab.frame()`（繞著機體的轉盤鏡頭，拖曳、滾輪、閒置自轉）與 `lab.animate()`（用選好的動作、武裝與手持武器組出 `animateMech` 的狀態，揮砍會照該武器的連段循環播放）。左側零件樹由設計資料遞迴產生，點畫面上的機體則用 Raycaster 找到網格、從 `userData.part` 得到零件（建構器替每個物件記下它的來源零件與左右側）；選到的零件用 `BoxHelper` 框起來，並帶著 `engine/render/gizmo.js` 的操作把手直接在 3D 畫面裡拖：三支箭頭移動（W）、三個圓環旋轉（E）、三個方塊改尺寸（R），固定螢幕大小、畫在最上層、用看不見的粗碰撞網格挑選；每支把手各自定向，所以軸不必正交——箭頭沿父節點的軸（位置是父空間座標）、圓環繞 Euler 各分量真正轉動的軸（`eulerAxes`）、方塊沿零件自己的軸。拖曳的量用「滑鼠射線到軸的最近點參數」（`rayAxisParam`）、「射線與平面的交點」（`rayPlanePoint`，拖零件本身時平面與鏡頭垂直）與「交點在平面裡的角度」（`angleInPlane`）算出，鏡像零件的 x 與 y/z 旋轉乘上該側的正負號；按住 Shift 吸附到 0.25 m／15°。拖曳中只動現場的物件（連同動畫師的 rest 姿勢；改尺寸則換上一顆不進共用快取、拖完就釋放的幾何），放開才透過 `onDesign` 重建並留下一筆復原；沒移動的點擊不留痕跡，Esc 取消回到拖之前。右側欄位直接改零件物件（尺寸、位置、旋轉以度顯示、材質、鏡像、`only`），每次修改先把目前設計的 JSON 推進復原堆疊、原廠設計 `AX01` 不動（第一次修改時先複製），再透過 `onDesign` 讓遊戲以 `rebuildMechs()` 重建兩台機體（對手套紅色配色）並存進 `localStorage` 的 `skyline.mechDesign`；啟動時若有存檔且 `validateDesign()` 沒有問題就用它。匯出是 JSON 檔，匯入先驗證再採用；恢復預設把 `AX01` 交回去並刪掉存檔。

**武器模型**：右手的 `weapon` 群組底下每種武器一個模型（`rocket`、`longrifle`、`handcannon`、`saber`、`greatblade`、`knife`，名稱就是 `WEAPONS` 裡的 id），動畫器依 `rangedId`／`meleeId` 與目前的槽位只顯示其中一個；近戰模型內有 `edge`、`aura`、`bladeBase`、`bladeTip`，刀光拖尾從目前顯示的那把（`mech.activeMelee`）取端點，所以同名節點在不同武器裡不衝突。以前用縮放同一把刀槍冒充三種武器的 `bladeScale`／`GUN_SCALE` 已移除。

### 5.9 音效

`engine/audio/synth.js`：Web Audio 即時合成，不用音效檔。遊戲以 `createSynth(recipes)` 註冊「名稱 → 配方」，配方只用 `tone()`（振盪器掃頻）與 `noise()`（濾波白噪）兩種積木，加上 `throttle()` 防止連發疊音；每個聲音依相對鏡頭的位置算出左右聲像（StereoPanner）與距離衰減，`setLoop()` 提供持續的噴射迴圈。`games/skyline/sound.js` 放配方與「模擬事件 → 音效」的對照（開火依武器、爆炸依彈種、揮砍、受擊／防禦／破防、跳躍落地衝刺、切換、鎖定、過熱、KO、選單）；鎖定提示只播本機玩家的。第一次點擊或按鍵才解鎖 AudioContext。

### 5.10 沙塵龍捲風

`games/skyline/rules/twisters.js`，數值在 `config.js` 的 `TWISTER`。舞台的 `hazards.twisters` 決定數量（沙漠 3 道）。

- **生命週期**：休息（3–8 s）→ 成形（3 s，強度 0→1）→ 存在（18–28 s）→ 消散（3 s）。每次成形從 6 個候選點挑「離最近的機體最接近 180 m」的那個（不會直接長在誰身上）。遊走：幾道正弦疊成的緩慢轉向，加一點朝雙方中點的偏向（才會穿過戰場），靠近圍欄時轉回中央，速度 9 m/s。
- **確定性**：不抽亂數。候選點與時長由每道龍捲風的種子和第幾次成形算雜湊，遊走只看世界時間，狀態是 `world.twisters` 裡的純資料，所以複本、快照與區網同步都不用特別處理（`hashWorld` 也納入）。
- **吸力**：60 m 內是「風」——加在移動要追的目標速度上（不是加速度，否則地面的煞車會把它吃掉）：中心邊緣向內 24 m/s、側向 18 m/s，往外平方衰減，再加上龍捲風本身的移動。全速跑開可以脫離，衝刺更快。
- **捲起**：進到 11 m 核心就被抓住：繞軸 26 m/s 旋轉並以 34 m/s 上升，機體跟著自轉，控制失效；升到 78 m 或滿 3.2 s 就被甩出（向外 42 m/s、上 14 m/s），甩出的動量在落地前不受空中限速影響，之後 3.5 s 不受任何龍捲風影響，所以會落在吸力範圍外。被抓住時衝刺可以直接脫身（同樣 3.5 s 免疫）。
- **子彈**：穿過核心 1.8 倍半徑內的投射物被往中心拉、沿旋轉方向推、稍微抬升，火箭砲擦過時大約偏 4–5°；純旋轉的力在直線穿越時會前後抵消，所以一定要有向內的分量。
- **畫面**（`engine/render/twister.js`）：兩層漏斗殼（開口圓柱在頂點著色器裡彎成漏斗並左右擺動，片段著色器用滾動雜訊做沙帶、輪廓處較濃）加 520 顆由 GPU 依時間計算位置的沙塵（三分之一貼地繞著底部），顏色隨時段變化並套用霧。聲音是每道龍捲風一個依距離衰減的低頻風聲迴圈。

### 5.11 練習模式

`games/skyline/rules/targets.js`、畫面 `engine/render/targets.js`，數值在 `config.js` 的 `PRACTICE`。`createWorld({ practice: { mode } })` 會放靶並建立 `world.practice`（得分、射擊數、命中數、擊破、靶心、假人傷害、計時階段）。

- **鏢靶**：依舞台與種子放 20 個——8 個街邊立靶（中心 14 m 高，正好是火神砲的高度）、5 個矮樓屋頂靶、3 個沿街 40–64 m 來回的移動靶、4 個 45–90 m 高繞圈的浮空靶；每個都檢查不碰任何方塊與匝道、彼此與出生點保持距離。靶會在支架上轉向玩家（1.6 rad/s），所以從哪裡都打得到。
- **命中**：投射物的線段與靶面圓盤求交（和牆、機體一起取最早的命中），依交點到圓心的距離分五圈。靶有耐久（30，浮空靶 20）：火箭砲、步槍一發打爆，火神砲要 4 發；打爆那一下的圈數決定得分，再乘上種類倍率。近戰的揮砍框碰到靶也算（固定 6 分起）。打爆 3.5 s 後重生。
- **假人**：座位 2，不會攻擊（站著，或沿出生點的街道橫移並定時跳躍、衝刺）。練習中沒有勝負：HP 歸零時播 KO 特效，3 s 後在出生點滿血站起來。
- **60 秒挑戰**：3 s 倒數（期間不計分、不計射擊數），60 s 計時，最後 5 秒倒數音，時間到停止計分並顯示結果；最佳紀錄依場景存在 `localStorage`。
- **HUD**：右上角得分面板、上方計時、倒數大字、每個靶頭上的菱形標記與距離（依種類上色，460 m 內）、命中時的「+分數」與「靶心」提示。

### 5.12 隕石（軌道站）

`games/skyline/rules/meteors.js`，數值在 `config.js` 的 `METEOR`，畫面在 `engine/render/meteors.js`。舞台的 `hazards.meteors` 帶著車道（街區之間的街道中線）位置。狀態是 `world.meteors` 裡的純資料，和龍捲風一樣不抽亂數：每顆隕石的路徑由它的種子與第幾趟算雜湊，流星的時間、目標、落點散布、俯衝角度由排程的種子與第幾發算雜湊，運動只有直線與世界時間，所以複本、快照、區網同步與 `hashWorld` 都不用特別處理。

- **漂流隕石**：16 顆球體（6 顆低、6 顆中、4 顆高；半徑 8–13／10–18／14–26 m），以 3.5–8 m/s 沿直線從圍欄外飄進來、穿過場地、從另一邊出去，再換一條新路徑回來，並緩慢上下浮動 1.2 m。低的貼著甲板（底部離地 1.5–3 m）沿車道漂；中的底部在 24–56 m（底下走得過機體）、高的在 85–150 m，可以走車道或斜穿。路徑在出發前每 6 m 檢查一次：離牆至少 13 m、離屋頂至少 20 m（加上浮動），所以機體永遠躲得開，不會被夾在隕石和建築之間；檢查不過就換下一條候選，最後退回一定空著的車道。開局時隕石已經散在路徑上，但不會壓在出生點。
- **碰撞**：機體移動完之後才和隕石處理（`rockContacts`）：被推出球體、朝隕石的速度被抵消、隕石的漂移速度帶過去；在甲板上只會被橫向推開，不會被壓進地板。腳在球心以上、又在頂部 80% 範圍內就算**站在上面**：貼著表面、算落地（有落地事件、燃料回復、可以起跳），隕石往哪漂就被帶著走；上一 tick 站著的會黏住隨浮動上下，除非正在往上跳。第一次撞到發 `bump` 事件。
- **擋子彈與視線**：投射物的線段和球體求交，和牆、機體、鏢靶一起取最早的命中，所以隕石是會移動的掩體；鎖定的視線檢查也算隕石（用 0.9 倍半徑，擦邊不算），被隕石擋住 3 秒就失去鎖定。
- **流星襲擊**：開場 8 s 後第一發，之後每 6–10 s 一次，輪流打兩台機體（每第 4 次是三發的流星群：一發打機體、兩發落在 26–40 m 外，間隔 0.35 s）。瞄準機體腳下（往下找到甲板或屋頂）散布 9 m 內的一點，從 49–69° 的俯角以 260 m/s 飛 1.6–2.0 s 抵達；整段飛行期間落點都有紅圈（`meteorWarn` 事件），所以有一秒多可以跑開或衝刺。飛行中每 tick 用頭部半徑 2.5 m 的線段檢查甲板、建築、隕石與機體，碰到什麼就在哪裡炸（`meteorHit`）。
- **爆炸**：22 m 內的機體依到身體最近點的距離受 150→40 的傷害（類型 `blast`，裝甲不加減、防禦減半），並被往外拋（32 m/s、向上 16 m/s，越近越強）與 0.5 s 硬直；爆心看不到機體中心（牆或隕石擋著）就不受傷，所以躲到建築後面或隕石底下也行。被隕石擊倒時勝利歸另一台（`ko` 事件帶 `winner` 與 `cause: 'meteor'`）；勝負已定或 60 秒挑戰結束後不再落下。
- **畫面**：隕石是三種形狀的 InstancedMesh（細分的正二十面體依雜訊與幾個隕坑推凹凸、平面著色，表面在半徑的 0.86–1.0 倍之間，貼近模擬的球），每顆依 id 有色調與緩慢自轉；擋在鏡頭和自己機體之間時以有序抖動（不需排序）變成半透明，鏡頭進到裡面就完全消失；正下方的甲板或屋頂有隨高度變淡的軟陰影。流星是白熱的頭、120 m 長的錐形火尾（加色混合）、沿途散落的煙與火花；落點是會隨時間填滿、越接近越快閃的紅圈、內圈和一道紅色光柱。爆炸是白芯、火球、餘燼光、地面衝擊環、迎面的環、火花、碎石、升起的煙柱與鏡頭震動，留下 14 秒淡出的焦痕。站在紅圈裡時畫面邊緣會紅色脈動，並提示「隕石來襲！離開紅圈」。
- **聲音**：瞄準自己的流星有雙音警報（瞄準別人的是遠處的高音提示），飛行中有隨距離變大的呼嘯迴圈，落地是低沉的爆炸聲，撞到隕石是悶響。

## 6. AI

`games/skyline/ai/`：`brain.js` 每 tick 產生一份和玩家一樣的 Intent，`nav.js` 是導航網格，`arena.js` 讓電腦互打（平衡工具與測試共用）。同一個種子結果一樣。

- **感知**：只用 `lockLos`（有視線）時的對手位置與速度；失去視線後記住最後位置，0.4 s 後進 search 模式走過去找（所以躲進巷子真的有用）。
- **導航**：由 Stage 的 statics 建 6 m 網格（擋到 18 m 機體高度的方塊膨脹 4.5 m 後標為不可走），8 向 A*（不切角）加拉直；高架與匝道的柱子自然在網格裡。遠程型會挑 20–50 m 的矮樓用噴射上樓頂（climb 模式）。
- **戰術**：approach／search／engage／retreat／climb 五個模式，engage 時繞著目標橫移並往該武器類型的理想距離飄（普通 50–130 m、遠程 110–230 m、近戰貼身）。武器依距離、高度差和**對手的裝甲**挑：對手防遠程就縮短距離用刀砍，對手防近戰就保持槍程、少揮劍。遠程武器會算提前量與下墜；來襲彈道夠近就衝刺閃開，對手起手近戰就防禦或閃。
- **難度**（`AI_LEVELS`）：反應時間 0.7／0.3／0.12 s、決策間隔、瞄準誤差 0.07／0.03／0.012 rad、閃躲率、防禦率、連段率、會不會上樓頂、衝刺率、提前量、重算路徑頻率。
- **危險地形**：繞開龍捲風的吸力範圍，被捲住時衝刺脫身；軌道站上每發流星落在附近時擲一次「要不要躲」（簡單約 37%、普通 60%、困難 90%），反應時間過後往紅圈外跑，快落地還在圈內就朝外衝刺；也會避開同高度的隕石。測試裡困難的電腦被瞄準它的流星打中不到三成，站著不動的機體七成。

## 7. 區域網路

主機權威，沿用整套基礎設施：`server/lan-server.js` 原封不動（它只轉送文字與廣播房間），大廳、房間探索、`/api/*` 照用。同一個伺服器只有兩個座位：先連上的是座位 1，也就是主機。

**同步方式（實作版）**：主機權威的鎖步加來賓預測，在 `engine/net/sync.js`，與遊戲無關（吃 `stepWorld`、`cloneWorld`、`serializeWorld`、`applySnapshot`）。

- 兩邊都跑同一份確定性的模擬。主機每 tick 用自己的 Intent 加上來賓送來的那個 tick 的 Intent（沒到就沿用上一個：移動、視角、按住的鍵延續，按下的鍵不重複；遲到的「按下」併到下一個 tick，不會丟）。主機永遠不等人。
- 主機每幀送出這一幀走過的 tick 各用了哪一對 Intent（`tk`），每 60 tick 附一份完整快照。來賓有一份**已確認世界**照著重播（模擬確定時與主機逐 bit 相同，不確定時被快照拉回），畫面則畫**預測世界**：已確認世界往前推到自己的現在，用自己已排程的輸入，主機那邊沿用最後一次輸入。
- 來賓的輸入標在「現在 + delay」tick 送出（預設 2 tick ≈ 33 ms，依主機回報的遲到次數自動在 2–8 之間調整），所以通常準時抵達、不需要修正；自己的機體立刻反應，對手的機體最多外插一、兩個 tick。
- Intent 以 `[moveX, moveZ, yaw, pitch, heldBits, pressedBits]` 傳送，數字走 JSON double 不失真；-0 會被正規化（`atan2(-0, -1)` 與 `atan2(0, -1)` 不同，足以讓兩邊分岔）。
- 事件（音效、特效）只從已確認世界播，所以不會播出沒發生的命中；延遲約單程網路時間。
- 大廳協定在 `games/skyline/lobby.js`：`hi`（遊戲與版本、配置）、`pick`、`ready`、`start`（種子與雙方配置）、`again`、`lobby`。對手離線時進「對手離線」畫面，可以留在房間等人。
- 測試：`games/skyline/tests/net.test.js` 用假網路（可設延遲）跑主機與來賓 900 tick，驗證已確認世界雜湊相同、事件數相同、延遲鏈路上按鍵不遺失、被破壞的來賓會被快照拉回；`tools/skyline-lan-smoke.mjs` 用兩個 headless 瀏覽器走過建房、加入、準備、開打、選單、離線。兩台實體電腦的互連尚未實測。

## 8. 測試與效能

**Node（ESM）**：AABB 與線段相交、控制器（踏階、斜坡、落在樓頂、不穿牆）、投射物命中與視線、傷害矩陣、切換冷卻、KO、城市產生器同種子同輸出、導航網格與 A*、AI 會打人、9×9 配置平衡回合賽（固定種子）。

**Playwright**：載入遊戲頁、等第一幀、檢查 console 無錯誤、截圖存檔供人工看；進入戰鬥並送假輸入 3 秒確認沒有例外。這個環境的 headless Chromium 有 WebGL2，可以跑。冒煙測試也會產生單檔版並從 `file://` 開啟、開一場戰鬥。

**單檔下載版**（`tools/skyline-standalone.js`，`npm run build:standalone`）：把 `index.html`、48 個模組與 vendored Three.js 包成一個約 1.6 MB 的 HTML。每個模組以 base64 `data:` URL 放進 import map；`data:` 模組沒辦法解析相對路徑，所以建置時把相對 import 改寫成 `@skyline/<從 repo 根目錄的路徑>`，由 import map 對應（`three`、`three-addons` 照舊）。雙擊就在瀏覽器開，不需要伺服器（`file://` 不能 fetch 其他模組，內嵌的 `data:` 模組沒有這個問題）；自己是頂層頁面，所以能鎖定滑鼠。沒有伺服器時大廳偵測直接回報「沒有伺服器」，區網按鈕停用；設定與紀錄照樣存在瀏覽器。

**效能預算**（1080p、內顯 60 fps）：draw call < 150（建物與窗戶 instancing）、三角形 < 300k、bloom 半解析度、模擬每 tick < 1 ms。畫質等級：低（無後製、無真陰影）／中／高。

## 10. 決定（2026-10-09 確認）

1. **名稱與路徑**：`Gravity Duel: Skyline`、分支 `skyline`、`games/skyline/`。建議就這樣，名字之後可改。
2. **Three.js 依賴**：引入一個外部函式庫，代價是必須走 HTTP、不能雙擊 index.html。建議接受；桌面版與 artifact 本來就走 HTTP。
3. **第一版模式**：單人 + 區網；同機雙人（分割畫面）放 M5。建議接受。
4. **遠程瞄準方式**：已決定「按住瞄準鍵才進第一人稱，放開就回第三人稱」，像射擊遊戲的 ADS。
5. **躲藏規則**：對手血條只在有視線時顯示，沒視線改顯示最後位置的箭頭（建議）。另一種是血條永遠顯示，躲藏就只剩擋子彈。
6. **原作不動**：這個分支不改 `src/`；之後要不要把原作搬到 `games/gravity-duel/` 並改用 `engine/`，等 Skyline 的引擎穩定再決定。

## 11. 下一款遊戲怎麼用這個基礎

新遊戲 = 一個 `games/<name>/` 資料夾，提供第 4 節的 Game 介面：

1. `config.js`：單位、按鍵、數值。
2. `rules/`：`createWorld`、`step`、`serialize/apply`。只要是「純資料進、純資料出」，引擎的迴圈、區網、測試工具都直接可用。
3. `stages/`：輸出 Stage 資料。有 `statics`/`ramps` 就有碰撞、視線、導航網格；有 `visual` 就有畫面。
4. `mechs/`：零件樹。節點名稱一致就有動畫。
5. `screens/`：選單內容。畫面堆疊與雙方準備邏輯在引擎。
6. `ai/`：產生 Intent 的函式。

不想要 3D 的遊戲也能只用 `core`、`input`、`net`、`ui`、`audio`：原作就是這種形狀。
